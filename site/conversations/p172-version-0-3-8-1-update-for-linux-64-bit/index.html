Version 0.3.8.1 update for Linux 64-bit

BitcoinTalk forum · 14 messages · from 9 August 2010 · with ArtForz, Ground Loop, NewLibertyStandard, Satoshi Nakamoto, dkaparis, jgarzik…

Read in Satoshi Mail Archive source

Satoshi Nakamoto · 9 August 2010, 19:46 UTC · original
When we switched to Crypto++ 5.6.0 SHA-256 in version 0.3.6, generation got broken on the Linux 64-bit build.  Version 0.3.8.1 is on SourceForge with the 64-bit binary updated. Download: http://sourceforge.net/projects/bitcoin/files/Bitcoin/bitcoin-0.3.8/bitcoin-0.3.8.1-linux.tar.gz/download Future versions after 0.3.8 will probably require SSE2.  Anyone have Pentium 3 or older where this would be a problem?
NewLibertyStandard · 9 August 2010, 20:26 UTC · original
The difficulty has gotten high enough that I wouldn't worry about dropping block generation support for old computers if it's hard to maintain compatibility. But the client should definitely provide some feedback explaining why the feature isn't available. Perhaps you could make a message pop up that explains why generating bitcoins is not supported on old hardware.
jgarzik · 9 August 2010, 20:46 UTC · original
IMO, SSE should be required for generation, not simply to run the client.
Satoshi Nakamoto · 9 August 2010, 20:55 UTC · original
That's a good point, I believe you could run with generation off if you don't have SSE2. How about add to the top of cryptopp/config.h: #if !defined(_M_X64) && !defined(__x86_64__) #define CRYPTOPP_DISABLE_SSE2  1 #endif that would disable SSE2 for 32-bit builds.  (at least with GCC or MSVC)
dkaparis · 9 August 2010, 20:57 UTC · original
From what I understand, removing the offending define is required only for 64-bit builds and 64-bit architectures are already guaranteed to support SSE2 instructions. 32-bit builds can retain the flag and thus continue to disable SSE2 instructions and remain compatible with older computers.
